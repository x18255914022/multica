# Перевод проекта Multica на русский язык: план и оценка

Дата анализа: 2026-10-22. Рабочее дерево кода не изменялось — только этот документ.

## 1. Как в проекте устроена локализация (факты из кода)

Проект **уже мультиязычен «из коробки»**: добавление нового языка — это конфигурация + словари, а не переписывание кода. Поддерживаемые сейчас локали: `en` (дефолт), `zh-Hans`, `ko`, `ja`, `fr` (`packages/core/i18n/types.ts`). Для русского языка ничего не занято — плагин `ru` добавляется по готовому шаблону (последним так добавляли `fr`).

Слои, которые нужно перевести (по убыванию объёма):

| # | Слой | Где живёт | Объём EN | Примечания |
|---|------|-----------|----------|------------|
| 1 | UI приложения (web/desktop) | `packages/views/locales/en/*.json` — 25 пространств имён i18next | **≈13 747 ключей** | Есть guard-тесты: `parity.test.ts` (каждый ключ EN обязан существовать во всех локалях и наоборот) и `mcp.test.ts`. Пустой перевод = падение CI, поэтому нужен полный пакет сразу |
| 2 | Landing-страница web | `apps/web/features/landing/i18n/{en,ja,ko,zh}.ts` | ~250 КБ TS-кода со строками | Функция `createEnDict()`; тип `LandingDictionaryLocale` допускает reuse чужого словаря (как `fr` → `en`), но для настоящего перевода нужен свой `ru.ts` |
| 3 | Документация | `apps/docs/content/docs/**.mdx` | 235 MDX-файлов (EN-bазовых ~88, остальные — варианты `.zh/.ko/.ja/.fr`) | Fumadocs, суффиксы в имени файла; `docsHrefForLocale()` уже поддерживает `/docs/…` |
| 4 | Мобильное приложение | `apps/mobile/locales/{en,zh-Hans}` | отдельный компактный набор | Автономный клиент; свои тесты parity |
| 5 | Серверные user-facing строки | Go: `server/internal/handler/auth.go` (`supportedLanguages`), `mika_agent*.go` (тексты агента Mika per-language), `integrations/wecom/strings.go` (пакеты строк WeCom-интеграции) | единицы–десятки строк | Валидация `language` при PATCH /api/me обязана включать `"ru"`, иначе значение не сохранится |
| 6 | README/маркетинг | `README.md` (+ есть паттерн `README.zh.md`, `VISION.zh.md`) | — | Опционально |

Не переводятся (и не должны): код, комментарии, логи (`slog`), имена событий, OpenAPI-схемы, промпты агентов (это продукт-контент для LLM).

## 2. Что нужно сделать технически (чанджлист)

### 2.1 Ядро (блокирующее всё остальное) — ≈10 файлов правок
1. `packages/core/i18n/types.ts`: добавить `"ru"` в union `SupportedLocale` и массив `SUPPORTED_LOCALES`.
2. `server/internal/handler/auth.go`: добавить `"ru": {}` в `supportedLanguages` (зеркалирует пункт 1; в коде прямо написано «keep both lists in sync»). Без этого выбор RU отклонится API и не синхронизируется между устройствами.
3. `packages/views/locales/index.ts`: импорт 25 JSON-файлов `./ru/*.json` + запись `ru: {...}` в `RESOURCES`.
4. `packages/views/settings/components/preferences-tab.tsx`: опция `{ value: "ru", label: t($.preferences.language.russian) }` + новый ключ `russian` во **всех** существующих локалях (parity!).
5. `packages/core/i18n/pick-locale.ts` (+ тесты): маппинг `ru*` → `ru` при автоопределении по языку браузера.
6. `apps/web/lib/docs-href.ts`: `if (locale === "ru") return "/docs/ru";`
7. `apps/web/features/landing/i18n/types.ts`: `ru: "RU"` в `localeLabels`; решение по `toLandingDictionaryLocale` (см. 2.2).

### 2.2 Словари (основная работа — контент)
- **Перевод 13 747 строк** `packages/views/locales/en/*.json` → `ru/*.json` (самые крупные: issues 3223, agents 1778, settings 2529, autopilots 927, runtimes 838). Сохранять плейсхолдеры `{{var}}`, `_one/_other` (в русском правила plural i18next: one/few/many/other — проверить настройку `pluralRules`/`compatibilityJSON`; zh обходится одним `_other`, с русским так не выйдет — потребуется расширить нормализацию в `parity.test.ts` под славянские формы).
- Landing: либо временно reuse `en` (официальный путь проекта — именно так сейчас живёт `fr`), либо полноценный `ru.ts` (~250 КБ copy).
- Docs: ~88 базовых MDX → файлы `*.ru.mdx`.
- Mobile: `apps/mobile/locales/ru/*` + регистрация в `resources.ts`/`config.tsx` (там сейчас захардкожены только en/zh-Hans).
- Go-строки: pack `ru` в wecom/strings.go (если интеграция актуальна), тексты Mika в `mika_agent*.go`/`mika_onboarding*.go` (таблица language→string).

### 2.3 Проверка
```bash
pnpm --filter @multica/views test          # parity.test.ts + mcp.test.ts — главный гейт
pnpm typecheck && pnpm lint && pnpm knip   # типы RESOURCES/SupportedLocale подтянутся автоматически
make test                                   # Go: user_language_test.go и др.
pnpm --filter @multica/web build            # landing dictionary.test.ts
```

## 3. Оценка сложности

| Вариант | Трудозатраты | Комментарий |
|---|---|---|
| **A. RU только в приложении (web+desktop), landing/docs на EN** | **~1–2 недели**: 1–2 дня кода (чанджлист 2.1) + машинный перевод 13,7 тыс. строк с вычиткой носителем 3–7 дней | Самый реалистичный MVP; проект явно делался для поэтапного добавления локалей |
| B. Полностью (app + landing + docs + mobile + Go) | ~4–8 недель с человеком-ревьюером | Объём контента: ~15 тыс. UI-строк + ~250 КБ лендинга + 88 MDX |
| C. Быстрый hack («переключить интерфейс») | <1 дня, но **не работает как следует** | Можно лишь заменить содержимое `en/*.json` на русский текст без регистрации новой локали — сломает fallback для англоязычных пользователей и противоречит архитектуре; не рекомендуется |

**Вывод: сложность низкая–средняя.** Архитектура специально построена под добавление языков: один union-тип + зеркальная Go-валидация + JSON-словари + два теста-гаранта. Ни одна часть системы не требует редизайна. Основные затраты — качество перевода 13,7 тыс. строк и нюансы русской плюрализации в i18next.

## 4. Риски/подводные камни
1. **Plural-формы**: i18next для ru требует `one/few/many` — проверьте `compatibilityJSON: 'v3'` или явные `_few/_many` ключи; иначе сообщения «N issues» будут битыми.
2. **Parity-тесты падают на неполных переводах** — заводить `ru/` надо сразу полным пакетом (или временно исключать locale из теста, что заметно в PR).
3. **Двойной список локалей** (TS + Go) — классический источник рассинхрона; добавьте тест, сравнивающий оба (в Go уже есть `user_language_test.go`).
4. **Desktop** наследует всё из `packages/views` — отдельных правок почти нет, кроме настроек Electron-локали если требуется.
5. Строки внутри скриншотов/демо в лендинге и маркетинговых ассетах (`docs/assets`) в код не входят.

## 5. Рекомендуемая последовательность
1. Чанджлист 2.1 + пустой заглушечный пакет `ru` с копией EN-значений (проходит parity) → зелёный CI, RU появляется в селекторе.
2. Поэтапная замена значений на перевод (namespace за namespace: common → auth → settings → issues → …), CI-guard держит паритет.
3. Landing/docs/mobile — вторым релизом.
